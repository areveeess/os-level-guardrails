<objective>
Make every result record self-describing and every run paired and resumable like-for-like (EVAL-06 and the runner side of EVAL-05): stamp each record with the code commit, policy-file hash, provider, resolved model id, per-step finish_reason and prompt_tokens; surface those stamps in the report; re-queue infrastructure-errored episodes; keep arms paired in an interleaved queue; and write a manifest per results directory.

Purpose: Phase 4 resumes hosted runs across days and quotas and adds local models whose prompts may be silently truncated. Without stamps a resumed run that crossed a code or policy change, a model id that drifted server-side, or a prompt cut by a context window is undetectable, and a quota cut-off in the current case-major order leaves only direct-harm episodes. Plan 01-01 already drops infra-errored pairs from the statistics; this plan makes the runner re-run them.
Output: stamped records (src/llm/base.py, src/llm/openai_compat.py, src/agent_harness/loop.py, src/benchmark/runner.py), a "## Provenance and data quality" report section and manifest-driven completeness (src/benchmark/report.py, run_benchmark.py), tests/test_provenance.py, tests/test_runner_queue.py.

Edge-case predicates (records without stamps, git unavailable, provider without finish_reason, quota stop during re-queue, refusals never retried, secrets absent from outputs) were authored by the planner from the requirement text; no SPEC or edge probe exists for this phase.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider API -> runner | finish_reason and model id come from a remote (or local Ollama) server and are stored and rendered verbatim |
| runner -> results directory | raw.jsonl and manifest.json are long-lived evidence and may be shared with reviewers |
| runner -> git subprocess | The runner shells out to read the commit |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Repudiation | raw.jsonl records from resumed, mixed or truncated runs | medium | mitigate | Every row stamped with code_commit, code_dirty, policy_sha256, provider, resolved_model, finish_reasons, prompt_tokens; manifest.json logs each invocation; the report marks MIXED commits/policy hashes and counts length stops |
| T-01-12 | Information disclosure | manifest.json and raw.jsonl | medium | mitigate | The manifest has a fixed field list with no environment values; tests/test_runner_queue.py sets a fake GROQ_API_KEY and asserts it appears in neither file |
| T-01-13 | Tampering | resolved model id rendered into summary.md | low | mitigate | Rendered through plan 01-01's _cell escaping |
