<objective>
Lay the shared data foundation for both local models: the compact transcript format version 2 (tool names with required parameter names on the T: line, 2048-character context), the episode schema with full tool specs, training text that is literally the inference renderer's output plus the gold action (parity by construction), the loss mask, the strict leakage gate, and a reproducible generator whose first slice emits benign episodes from real non-benchmark tools. Plan 02-02 grows the generator to the full 50/25/25 attack mix and dev split; plan 02-03 trains and serves the model on top of this.

Purpose: SCRATCH-02 and SCRATCH-03 are what make any ScratchGPT number defensible in the viva: the model was never shown a benchmark tool, address, canary or sentence, and it reads at inference exactly the text it was trained on. These are torch-free CPU tasks that must be right before any GPU time is spent.
Output: src/scratch_llm/{__init__,format,dataset,templates}.py committed (model.py tracked with context 2048), .gitignore entries for weights and episode files, tests/test_format_parity.py and tests/test_training_leakage.py.

Decisions implemented: D-04 (strict hold-out, with the held-only parameter-name rule scoped exactly as clarified in CONTEXT.md commit 912a8ab: it applies to tool parameter names on the T: line / in tool specs and to call_tool argument keys; the same ordinary words, such as to, subject or url, in free text — U: requests, O: observation values, respond messages — are allowed and not gated; the scope is recorded in the dataset manifest by plan 02-02), D-05 (format version 2, context 2048, version / vocab / fingerprint constants), D-06 (training text from render_context, loss only on A: payloads plus newline). Edge-case predicates in must_haves were authored by the planner from the requirement text and research; no SPEC or edge probe exists for this phase.

Planner deviation from 02-RESEARCH.md, recorded here: the research gate rule "no tool whose required-parameter signature equals a held-out tool's" is applied to synthetic tools only. Measured this session, 77 of the 251 free-pool tools (34 of them with an empty signature) share a required signature with some held-out tool, so applying the rule to real tools would delete a third of the pool for no leakage benefit (those are real non-benchmark tools). Also measured: the benchmark text contains 6 distinct e-mail addresses, not 2; the gate derives them programmatically.
</objective>
