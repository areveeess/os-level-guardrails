<objective>
Grow the plan 02-01 generator into the full training distribution: the deterministic 50/25/25 benign / direct-harm-compliant / data-stealing-compliant mix with self-written injections (D-01), OS-action benign episodes (D-02), blocked-tail episodes that end with the harness's own refusal text (D-03), synthetic tools that force copying of unseen names and parameters, observation styles built from each tool's return schema, and a dev split that holds out both tools and phrasing templates (D-04). Then add the command-line entry point, generate the real 40,000 + 2,000 episode files and commit their manifest.

Purpose: SCRATCH-01 is the data the weak, unaligned ScratchGPT learns from (and Phase 3's LoRA reuses). Its mix decides how the model behaves under attack, so it must be exact, reproducible and disclosed; its dev split is how training is tuned without ever touching the benchmark.
Output: src/scratch_llm/dataset.py and templates.py extended, src/scratch_llm/provenance.py (new), tests/test_scratch_dataset.py (new), the generated data/local/*.jsonl (ignored) and data/local/manifest.json (committed).

Decisions implemented: D-01 (exact quota), D-02 (interpreted as about 10% of all episodes, all taken from the benign half, i.e. about one benign episode in five), D-03 (about 8% of dh/ds), D-04 (dev split with held-out dev tools and held-back templates; every split passes the gate). Claude's discretion used: 40,000 train + 2,000 dev episodes, 35% synthetic-tool share, dev tools = seeded 10% of the free pool. Edge-case predicates were authored by the planner from the requirement text and research; no SPEC or edge probe exists for this phase.
</objective>
